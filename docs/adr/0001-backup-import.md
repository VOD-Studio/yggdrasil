# 备份导入：独立 multipart 路由、两步式恢复、签名强制

备份恢复 tab 新增「导入」：把本系统生成的 `.sql` 备份从本机回灌到 `backups/`。

关键决策与理由：

1. **两步式（导入入库 → 列表点恢复）而非一步直连恢复。** 恢复路径保持唯一（`RestoreBackup` + 任务轮询 + 二次确认零改动），导入产物在列表可审计、可复用。
2. **新 multipart 路由流式落盘，不走 server fn。** server fn 走 JSON 序列化，无法承载数百 MB 文件；流式写盘避免整文件进内存。上限 env `BACKUP_IMPORT_MAX_MB`（默认 512MB），路由单独配 600s 超时。
3. **导入时即强制签名校验**（首行 `-- YGGDRASIL BACKUP v1`），非本系统文件拒收且不留盘。不开放任意 SQL 导入——「上传任意 SQL 一键执行」的误操作面不值得换跨站迁移便利（那走手动 psql）。
4. **配对的 `_uploads.tar.gz` 不支持导入。** uploads 还原本来就只能手动（tar 覆盖文件风险高，有意不自动），为其加导入 UI 收益低、需防 tar 炸弹/路径穿越。
5. **保留原始文件名，同名冲突拒绝。** 覆盖是破坏性的，自动改名制造双胞胎。名为 `auto_` 前缀的导入文件会参与自动轮转（语义自洽，UI 提示写明）。

部署连带后果：生产 nginx `client_max_body_size`（现 12m）必须调大到略超 `BACKUP_IMPORT_MAX_MB`，否则反代先于应用拒绝。
