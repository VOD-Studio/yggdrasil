# rua.plus 首屏性能实测（v1.1.1，2026-10-28）

线上版本 `v1.1.1`（`685a1b4f`），经 EdgeOne 访问 `https://rua.plus`。这是优化前的基线。

## 测量方法

- 工作站 headless Chromium，每次新建浏览器上下文、禁用缓存，取 3 次中位数。
- 桌面：1440×900，不限速。
- 移动：390×844、DPR 3，1.6 Mbps / 150 ms RTT，CPU 降速 4 倍。
- 「去 preload」：拦截 HTML，删除全部 `<link as="fetch" rel="preload" type="application/wasm">` 后再加载。
- 水合完成：`html[data-hydrated]` 出现的时间（`performance.now()`）。
- 工作站流量经过本地透明代理（fake-IP 198.18.x），同一路由多轮之间有明显波动，表中数据只看趋势。

## 发现的问题

1. **WASM preload 泛滥。** `/` 的 `<head>` 里有 363 个 `<link rel="preload" as="fetch" type="application/wasm">`，去重后 270 个，单个文件最多重复 5 次，占原始 HTML 51 KB（全文 125 KB）。来源是 `leptos_integration_utils-0.8.9/src/lib.rs:77-94`：每个预取的 lazy fn 都把清单里的全部分包展开成 preload，不去重；第 90 行还把 nonce 填进了 `crossorigin`。弱网下这些 preload 和 CSS 抢带宽：去掉后移动端 FCP 减少 0.5–2.5 s，水合完成时间不变。`/post` 不输出这些链接。
2. **主入口每次整包下载。** `/pkg/yggdrasil.*.wasm`（brotli 317,693 B）和 `.js` 返回 `cache-control: public, no-cache`。源站对 `If-None-Match` 返回 304，但经过 EdgeOne 一律返回 200 加完整包体（EdgeOne 不缓存 `no-cache` 资源，也不把条件请求转给源站），回访用户每打开一个页面都重下 317 KB。
3. **分包过碎。** 每个页面请求 330–700 个 WASM 分包，大多不到 1 KB；水合完成桌面 0.8–3.7 s，移动 3.8–6.9 s。
4. **EdgeOne 配置**（`tccli teo DescribeL7AccSetting` / `DescribeL7AccRules`）：缓存遵循源站；缓存键为完整 URL（`?v=` 能失效缓存）；QUIC 关闭；一条规则把 `jpg/png/gif/bmp/svg/webp` 的浏览器缓存统一改成 3600 s；HTML 在 EdgeOne 一直 MISS，由源站 SSR 缓存兜底。

## 优化与本地对照

针对上面的问题做了三项改动（EdgeOne 另见下一节）：

1. `app::HydrationScriptsWithoutSplitPreload` 取走 `WasmSplitManifest`，HTML 只预载主包 wasm 和分包加载器。
2. `build-release.ts` 按入口 JS、主 wasm、加载器三者的最终内容重新命名，`hash.txt` 写入 `entry: content-addressed`，服务端据此对入口返回 `immutable`。
3. cargo-leptos 改用分包合并补丁版 wasm-split（`VOD-Studio/wasm-split-prototype` 的 `ygg/chunk-merge`，`8ca741dd`）。

对照方法：同一份服务端与 Rust 产物，只用 `WASM_SPLIT_CHUNK_LOAD_COST=0` 关闭合并重新构建前端，得到「未合并」组。两份 release 各起一个服务端，连本机开发库，前面套一个本地 HTTP/2 TLS 代理（避免 HTTP/1.1 的 6 连接限制放大请求数的影响）。冷缓存，每格取 3 次中位数。两组都已去掉分包 preload，所以这里只比较分包合并的效果。

## EdgeOne 调整（2026-10-28，`tccli teo`）

改动前的配置备份在工作站 `~/.local/share/ygg-ha/edgeone-backup-20261028/`。

- 删除规则引擎里把 `jpg/png/gif/bmp/svg/webp` 浏览器缓存统一改成 3600 s 的子规则，浏览器缓存改为遵循源站：`/uploads/` 恢复为源站给的 `public, immutable, max-age=31536000`。
- 开启 QUIC，响应带 `alt-svc: h3=":443"`。
- 入口文件不需要额外规则：内容寻址后源站返回 `immutable`，按「遵循源站」即可在节点缓存。

第二轮（同日，备份在 `~/.local/share/ygg-ha/edgeone-backup-20261028-1818/`）：

- AI 爬虫处置（`BotManagementLite.AICrawlerDetection`）由托管挑战改为观察（Monitor）。原先 `GPTBot`、`ClaudeBot`、`Claude-User` 访问任何路径（包括 `POST /mcp` 与 `/feed.xml`）都只拿到约 990 B 的 `EO_Bot_Ssid` 挑战脚本，AI 客户端连不上 MCP，也无法代用户读文章。想按路径加例外规则，`ModifySecurityPolicy` 对任何 `ExceptionRules` 都返回 `InvalidParameter`（官方示例原样提交也失败，个人版套餐疑似不支持），因此改为全站观察，仍记录日志。
- HTTP→HTTPS 跳转由 302 改为 301。
- HSTS 由 `max-age=16070400; preload` 改为 `max-age=31536000`：preload 标记要求一年且 includeSubDomains，原配置并不满足；子域未确认全部 HTTPS，不开 includeSubDomains。
- 未改：WAF 托管规则保持仅观察（后台提交的 Markdown/代码易误判）；源站防护（只放行 EdgeOne 回源 IP）需要同时改两台服务器防火墙，未开启；源站组仍是手动切换权重。
