## 1. 一句话概括

`open-claude-ui` 的设计目标不是做一个“炫技 UI 库”，而是还原现代桌面 AI 客户端中那种：

> 安静、温润、可信、有质量感的编辑式界面；它靠低对比表面、发丝边框、陶土橙点缀和物理弹簧动效，而不是靠高饱和渐变、强发光和夸张弹跳。

如果用几个关键词描述：

- **Editorial Warmth**：人文、编辑排版、纸感。
- **Clay / Terracotta**：陶土橙作为唯一强品牌色。
- **Low-Contrast Surface Layering**：微亮度层级，不靠硬边框。
- **Hairline Border**：发丝线边框。
- **Physics-Based Motion**：弹簧、阻尼、质量。
- **Interaction Guardrails**：IME、滚动劫持、拖拽死区、容器响应式防御。
- **Zero Binary Asset**：不引入专有字体和录音资产。

## 2. 设计哲学

### 2.1 温润，而不是科技冷感

这套系统的第一视觉印象是“暖”。

它刻意避免：

- 赛博朋克式蓝紫渐变；
- 高饱和霓虹色；
- 强发光边框；
- 玻璃拟态滥用；
- 大面积品牌色铺陈；
- 厚重黑色描边。

它追求的是：

- 暖灰背景；
- 近白纸面；
- 温暖陶土橙点缀；
- 阴影极轻；
- 文本层级清晰但不刺眼；
- 界面像一本安静的现代编辑器。

### 2.2 克制

品牌色 `#d97757` 是系统里少数强情绪颜色，因此它被严格控制在：

- 主按钮；
- 焦点环；
- 状态呼吸点；
- 激活态；
- 少量强调文本；
- 拖拽 glow；
- 思考状态微光。

它不做大面积铺陈，也不承担背景色职责。

### 2.3 层级来自亮度差，而不是强轮廓

面板、卡片、输入区、弹层之间的层级主要靠：

1. 微亮度差异；
2. 发丝线；
3. 轻阴影；
4. 高度语义 token。

而不是靠：

- 2px 粗边框；
- 明显黑色投影；
- 强背景色分割。

### 2.4 动效有“质量”

这里的动画不是 `opacity 0 -> 1` 的机械过渡，而是模拟有质量的物体：

```text
m * x'' + c * x' + k * (x - x_target) = 0
```

也就是：

- `m`：质量；
- `c`：阻尼；
- `k`：刚度；
- `x`：当前位置；
- `x_target`：目标位置。

这套模型带来的直接感受是：

- 点击有按压反馈；
- 弹层有轻微落地感；
- 抽屉像磁吸归位；
- 消息气泡不是“闪现”，而是“进入”。

## 3. 色彩体系

### 3.1 品牌色：Clay / Terracotta

当前 `code-examples/cds-theme.css` 中的实现：

| Token                    |     Light |                       Dark | 语义         |
| ------------------------ | --------: | -------------------------: | ------------ |
| `--cds-clay`             | `#d97757` |                  `#d97757` | 主品牌色     |
| `--cds-clay-hover`       | `#cc5a36` |                  `#e08264` | Hover        |
| `--cds-clay-light`       | `#fbf3ef` | `rgba(217, 119, 87, 0.15)` | 极浅品牌底色 |
| `--cds-text-accent`      | `#d97757` |                  `#d97757` | 强调文本     |
| `--cds-fill-brand`       | `#d97757` |                  `#d97757` | 主按钮填充   |
| `--cds-fill-brand-hover` | `#cc5a36` |                  `#e08264` | 主按钮 hover |

设计意图：

- Light mode 下 hover 加深，保持纸面稳定；
- Dark mode 下 hover 变亮，符合深色界面交互惯例；
- 品牌色承担“焦点、确认、激活”，不是大面积装饰。

### 3.2 文本颜色

| Token                  |     Light |      Dark | 用途           |
| ---------------------- | --------: | --------: | -------------- |
| `--cds-text-primary`   | `#151515` | `#f5f5f5` | 主文本         |
| `--cds-text-secondary` | `#525252` | `#a3a3a3` | 次级文本       |
| `--cds-text-muted`     | `#8a8a8a` | `#666666` | 弱文本、占位符 |

文本颜色不是纯黑纯白，而是略带灰度，降低视觉攻击性。

### 3.3 透明度阶梯

系统使用 alpha token 构建交互填充和边框：

| Token           |              Light |                     Dark | 用途        |
| --------------- | -----------------: | -----------------------: | ----------- |
| `--cds-alpha-0` |    `rgba(0,0,0,0)` |    `rgba(255,255,255,0)` | 透明        |
| `--cds-alpha-1` | `rgba(0,0,0,0.05)` | `rgba(255,255,255,0.05)` | Ghost hover |
| `--cds-alpha-2` | `rgba(0,0,0,0.10)` | `rgba(255,255,255,0.09)` | 标准边框    |
| `--cds-alpha-3` | `rgba(0,0,0,0.20)` | `rgba(255,255,255,0.18)` | 强边框      |
| `--cds-alpha-4` | `rgba(0,0,0,0.35)` | `rgba(255,255,255,0.30)` | 重分割线    |

这层 alpha 体系让 hover / selected / border 不需要额外调色，直接复用同一亮度语言。

### 3.4 危险色

| Token               |     Light |      Dark |
| ------------------- | --------: | --------: |
| `--cds-fill-danger` | `#ef4444` | `#f87171` |

危险色用于确认对话框、破坏性操作，不与品牌 Clay 混用。

## 4. 表面层级与空间结构

### 4.1 当前 CSS 实现

`code-examples/cds-theme.css` 中的 Surface 阶梯：

| Token                   |     Light |      Dark | 语义              |
| ----------------------- | --------: | --------: | ----------------- |
| `--cds-surface-0`       | `#f5f5f3` | `#0b0b0a` | 页面底色 Canvas   |
| `--cds-surface-1`       | `#fcfcfb` | `#151515` | 侧边栏 / 中间层   |
| `--cds-surface-2`       | `#ffffff` | `#1a1a19` | 消息气泡 / 卡片   |
| `--cds-surface-3`       | `#ffffff` | `#20201e` | 输入区 / 高层表面 |
| `--cds-surface-popover` | `#ffffff` | `#222220` | 悬浮弹层          |

### 4.2 层级使用规则

- 页面永远比内容容器暗或更“远”；
- 输入区比页面更亮，制造“可输入终端”的引导；
- Popover 比普通卡片更亮或更实，保证浮层可读；
- Dark mode 下层级反转由 alpha 和微亮度共同完成。

### 4.3 设计特征

这套 Surface 体系的关键不是“颜色差异大”，而是：

- 差异小但稳定；
- 明度递进语义一致；
- 不依赖纯黑或纯白制造极端对比；
- 让界面看起来像纸面堆叠，而不是塑料卡片堆叠。

## 5. 边框与阴影策略

### 5.1 发丝边

Light mode：

```css
--cds-ring-hairline: 1px;
```

高分屏下会缩至：

```css
--cds-ring-hairline: 0.5px;
```

甚至：

```css
--cds-ring-hairline: calc(1px / 3);
```

目的：

- 避免 1px 线在高 DPI 屏幕上过重；
- 保持“纸面被切开”的精细感。

### 5.2 单闭合边框原则

这是组件规范里的重要规则：

> 如果外层容器已经有 border，内部次级按钮、chip、附件胶囊不应再加 border。

例如：

- Composer 外层已有 `inset 0 0 0 1px border`；
- 内部 Ghost 按钮、chip 使用填充色；
- 不出现“边框套边框”。

这能显著降低视觉噪点。

### 5.3 焦点环

焦点环不是简单的 outline，而是带品牌色的复合阴影：

Light mode：

```css
--cds-focus-shadow:
  inset 0 0 0 1px var(--cds-surface-1), 0 0 0 1.5px var(--cds-clay),
  0 0 6px 1px rgba(217, 119, 87, 0.25);
```

Dark mode 会增加光晕强度：

```css
0 0 8px 2px rgba(217, 119, 87, 0.35);
```

特征：

- 双层；
- Clay 色；
- 微光；
- 可见但不刺眼。

### 5.4 阴影尺度

Light mode 中阴影非常轻：

| Token                    | 典型用途        |
| ------------------------ | --------------- |
| `--cds-shadow-sm`        | 普通卡片        |
| `--cds-shadow-md`        | 弹层、菜单      |
| `--cds-shadow-lg`        | 大浮层          |
| `--cds-shadow-popover`   | Popover 双环    |
| `--cds-shadow-composer`  | 输入框          |
| `--cds-shadow-drop-glow` | 拖拽态 / 强调态 |

Composer 的 light 阴影只有：

```css
0 4px 20px rgba(0, 0, 0, 0.035)
```

这说明系统的空间感主要靠：

> 表面亮度 + 发丝边 + 极轻阴影

而不是厚投影。

## 6. 圆角拓扑

圆角是这套系统里最能体现组件性格的部分。

### 6.1 当前 CSS token

| Token                         |      值 | 用途           |
| ----------------------------- | ------: | -------------- |
| `--radius-xs`                 |   `2px` | 极小元素       |
| `--radius-sm`                 |   `4px` | 小控件         |
| `--radius-md`                 |   `6px` | 标准按钮       |
| `--radius-lg`                 |   `8px` | 常规交互按钮   |
| `--cds-panel-radius`          |  `10px` | 面板、卡片     |
| `--radius-xl`                 |  `12px` | 大按钮、代码块 |
| `--radius-2xl`                |  `16px` | 对话框         |
| `--cds-message-bubble-radius` |  `18px` | 用户消息气泡   |
| `--cds-radius-composer`       |  `20px` | 主输入框       |
| `--df-radius-pill`            | `999px` | 胶囊控件       |

### 6.2 规律

- 小控件：小圆角，保持精度。
- 面板：中等圆角，稳定。
- 弹窗：较大圆角，柔和不突兀。
- 输入框：20px，亲和力强。
- 分段选择器：999px，形成胶囊形态。

### 6.3 组件对应

| 组件              | 圆角气质             |
| ----------------- | -------------------- |
| 按钮              | 精准、克制           |
| Segmented Control | 胶囊、顺滑           |
| Chat Composer     | 大圆角、纸面容器     |
| User Bubble       | 柔和对话容器         |
| Dialog            | 稳定、正式           |
| Code Block        | 12px，技术感但不生硬 |

## 7. 字体与排版规则

### 7.1 不提交专有二进制字体

仓库策略：

- 不包含 `.ttf` / `.otf`；
- 不包含商业字体；
- 使用系统字体回退栈。

Tailwind 配置中包含：

```text
system-ui
```

以及常规系统字体序列。

这保证了：

- 版权安全；
- 包体干净；
- 各平台使用原生最佳字体渲染。

### 7.2 数字必须稳定

所有动态数字必须使用：

```css
font-variant-numeric: tabular-nums;
```

或者 Tailwind：

```text
tabular-nums
```

适用：

- 时间；
- 倒计时；
- token 用量；
- token 预算；
- 音频频率；
- diff 行号；
- 消息长度；
- 成本估算。

目的：

- 数字变化时宽度不抖动；
- 表格和代码对齐稳定；
- 避免流式输出时布局跳动。

### 7.3 深色模式字重补偿

仓库包含深色模式下的字重光学补偿规则，例如：

```css
.dark .font-medium,
.dark .font-semibold,
.dark .font-bold
```

这类规则用于对抗浅色文字在深色背景上的视觉膨胀或发虚。

### 7.4 图标光学对齐

行内图标通常需要垂直光学修正，文档体系提到类似：

```css
vertical-align: -0.125em;
```

目的是让图标和文字基线视觉对齐，而不是几何对齐。

## 8. 动效哲学：物理弹簧而非线性动画

### 8.1 核心原则

系统明确反对：

```css
transition: all 0.3s linear;
transition: all 0.5s ease;
```

推荐：

- Framer Motion spring；
- 精调 CSS cubic-bezier；
- 有质量、有阻尼、有收敛的运动。

### 8.2 二阶阻尼谐振子

`ClaudeMotionPresets.ts` 中包含数学求解器：

```text
m * x'' + c * x' + k * (x - x_target) = 0
```

并计算：

```text
ζ = c / (2 * sqrt(m * k))
```

其中：

- `ζ < 1`：欠阻尼，有过冲；
- `ζ = 1`：临界阻尼；
- `ζ > 1`：过阻尼，无过冲。

这意味着动效不是视觉猜测，而是可以用物理参数描述。

### 8.3 动效的三个层级

1. **触觉反馈**
   - 按钮按压；
   - 小控件；
   - 时间极短。

2. **内容进入**
   - 消息气泡；
   - 卡片展开；
   - Popover。

3. **结构移动**
   - 抽屉吸附；
   - 面板拖拽；
   - 分割条 snap。

## 10. CSS 缓动曲线与时间尺度

### 10.1 标准 CSS 曲线

`ClaudeMotionPresets.ts` 中定义：

| 名称            | 曲线                                 | 用途                 |
| --------------- | ------------------------------------ | -------------------- |
| `OVERSHOOT`     | `cubic-bezier(0.34, 1.3, 0.64, 1)`   | 气泡、胶囊入场       |
| `EASE_OUT_EXPO` | `cubic-bezier(0.16, 1, 0.3, 1)`      | 阴影、焦点、模糊渐变 |
| `DECEL`         | `cubic-bezier(0.165, 0.84, 0.44, 1)` | 抽屉滑入             |
| `SHARP_PRESS`   | `cubic-bezier(0.32, 0.72, 0, 1)`     | 按压缩放             |

### 10.2 常用时间尺度

从组件代码中可见：

|    时长 | 用途                           |
| ------: | ------------------------------ |
| `100ms` | 瞬时按压                       |
| `120ms` | 分段控件咬合                   |
| `150ms` | hover / scroll mask / 冷却窗口 |
| `200ms` | Composer / panel 过渡          |
| `220ms` | 阴影与边框过渡                 |
| `300ms` | 面板滑入                       |
|  `2.4s` | 状态呼吸灯                     |
|  `1.2s` | active pulse                   |

### 10.3 动效纪律

- 不做长时间漂浮；
- 不做夸张回弹；
- 不让动画阻塞交互；
- 不使用 `transition: all` 大范围模糊动画目标；
- 阴影、颜色、transform 分开控制；
- 动画应可被用户输入打断。

## 11. 滚动、渐隐与流式输出行为

### 11.1 滚动渐隐

`ScrollFadeContainer.tsx` 使用非线性 alpha mask，而不是简单线性渐变。

核心思想：

- 顶部和底部边缘不生硬切断；
- mask 随滚动位置动态调整；
- 动画时长约 `150ms`；
- 使用 `transition-[mask-image]`。

这类设计让长列表在视觉上像“自然淡出”，而不是被硬裁剪。

### 11.2 滚动 pinning 防劫持

`useClaudeScrollPinning.ts` 的核心规则：

```ts
performance.now() - lastUserInputAt > 150;
```

也就是：

> 用户手动滚动后，150ms 内不要强制接管滚动。

它还包含底部容差，例如约 40px：

- 用户接近底部时继续 pin；
- 用户向上离开底部时停止 pin；
- 流式输出不能 hijack 视口。

### 11.3 流式 UI 稳定性

为了防止 LLM 流式输出造成跳动，系统要求：

- 动态数字 `tabular-nums`；
- 高度变化使用稳定 spring；
- 滚动行为有冷却窗口；
- 行号和表格使用固定宽度；
- 状态切换有明确生命周期。

## 13. 交互防御规则

这部分是本仓库最重要的工程价值之一。

### 13.1 CJK IME 守卫

中文、日文、韩文输入法在选词或确认候选字时会触发 Enter。

如果直接监听：

```ts
if (e.key === "Enter") send();
```

会导致用户还没完成输入就把半成品消息发送出去。

正确写法：

```ts
const handleKeyDown = (e: React.KeyboardEvent<HTMLTextAreaElement>) => {
  if (e.nativeEvent.isComposing || e.keyCode === 229) return;

  if (e.key === "Enter" && !e.shiftKey) {
    e.preventDefault();
    handleSendMessage();
  }
};
```

必须同时处理：

- `isComposing`；
- `keyCode === 229`。

### 13.2 滚动劫持防御

LLM 流式输出时不能每来一个 token 就强制 scroll to bottom。

规则：

- 用户手动滚动后记录时间；
- 150ms 内不抢滚动；
- 底部 40px 容差；
- 用户离开底部后停止 pin；
- 用户重新回到底部附近才恢复 pin。

### 13.3 拖拽死区

拖拽类交互必须设置约 `4px` deadzone。

适用于：

- 侧边栏列表拖拽；
- 面板分割条；
- 画布拖动；
- Lightbox pan / zoom。

目的：

- 点击不被误判为拖拽；
- 鼠标微抖不触发 reorder；
- 手势意图更明确。

### 13.4 容器响应式

系统使用 `@container`，而不是只依赖 viewport。

原因：

- 组件可能出现在侧边栏、弹窗、分栏中；
- 组件真实可用宽度由容器决定；
- 只看 viewport 会误判空间。

典型行为：

- Segmented Control 在极窄宽度下隐藏文字；
- 只保留 icon；
- 防止 glyph break 和文本挤压。

## 19. 当前仓库中的规范差异

本仓库的 `AGENTS.md` 和 `code-examples/ClaudeMotionPresets.ts` 对弹簧预设存在两套不同描述。

### 19.1 `AGENTS.md` 中的规范意图

`AGENTS.md` 描述为：

| 预设                | 参数                                      | 特征                              |
| ------------------- | ----------------------------------------- | --------------------------------- |
| `SPRING_SNAPPY`     | `stiffness: 600, damping: 30, mass: 0.6`  | ζ 约 0.791，过冲约 1.8%，约 0.22s |
| `SPRING_BOUNCY`     | `stiffness: 400, damping: 25, mass: 0.8`  | ζ 约 0.612，过冲约 8.8%，约 0.38s |
| `SPRING_GENTLE`     | `stiffness: 220, damping: 24, mass: 1.0`  | ζ 约 0.809，过冲约 1.5%，约 0.48s |
| `SPRING_HEAVY_SNAP` | `stiffness: 1200, damping: 80, mass: 0.1` | ζ 约 1.826，过阻尼                |

### 19.2 `ClaudeMotionPresets.ts` 当前实现

| 预设                | 参数                                      |
| ------------------- | ----------------------------------------- |
| `SPRING_BOUNCY`     | `stiffness: 600, damping: 30, mass: 1.0`  |
| `SPRING_SNAPPY`     | `stiffness: 320, damping: 28, mass: 1.0`  |
| `SPRING_GENTLE`     | `stiffness: 380, damping: 18, mass: 1.0`  |
| `SPRING_HEAVY_SNAP` | `stiffness: 1200, damping: 80, mass: 0.1` |

### 19.3 结论

这可能是两种情况之一：

1. `AGENTS.md` 描述的是更新后的规范意图，但代码未同步；
2. 代码是实际实现，`AGENTS.md` 描述的是另一版逆向结论。

在真实开发中建议：

- 以 `AGENTS.md` 作为 agent 强制规范；
- 以 `ClaudeMotionPresets.ts` 作为当前可执行事实；
- 修改动效时先统一两者，再开始扩散组件。

另外，`AGENTS.md` 中描述的 Surface 色值与 `cds-theme.css` 当前实现也存在差异。例如：

- `AGENTS.md`：light Surface 0 为 `#fcfcfb`；
- `cds-theme.css`：light Surface 0 为 `#f5f5f3`。

同样建议先确认目标版本，再统一 token 源头，避免同一系统里出现两套“官方值”。
